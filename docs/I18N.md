# 多言語化 (i18n)

ゲームの文字を、日本語 (原文) のまま英語など他の言語でも出せるようにするための仕組みと決めごと。

- 原文は日本語。いまの言語は 5 つ: 日本語 (`ja`)・English (`en`)・한국어 (`ko`)・简体中文 (`zh-Hans`)・繁體中文 (`zh-Hant`)。英語は訳し終えている。韓国語・簡体字は、**土台 (言語の登録・フォント・折り返し・検査・空の表のスタブ) だけ** 作ってあって、訳はこれから (9 章が、訳す人への手順)。繁體字は簡体字から機械で作る (3 章の「繁體字」)。
- 次の言語を足すときも「翻訳表を1つ足す」だけで済むように作ってある (3 章)。
- フェーズ1 は仕組みと、画面の文字 (ラベル・ボタン・ダイアログ・トースト・システムメッセージ) まで。
- フェーズ2 は村の画面の文字と、データ表のうち量が少ないもの (村・ミッション・ギフト・メール・お知らせ・装備・ショップ・召喚バナー・地方と敵と曜日ダンジョンと遠征・チュートリアル)。
- フェーズ3 は、キャラ名・キャラの台詞・ストーリー・年間スケジュールとイベント・同盟のデータ、スキル (456 件の名前と説明)。規約は、その次 (入口の `tr()` は使えるようになっている)。
- フェーズ4 (このブランチ) は、韓国語・簡体字・繁體字の土台。訳そのものは含まない。

## 2. 仕組み

```
src/game/i18n/
  index.ts        t / tr / getLanguage / setLanguage ... (画面側はここだけ import する)
  core.ts         言語の状態、t()、{name} と複数形の展開、formatNumber
  languages.ts    言語の一覧 (LANGUAGES)、端末の言語の判定 (detectLanguage)、フォールバック順
  fonts.ts        fontFamily(kind, lang?): 現在の言語から文字のフォントを決める 1 か所の関数
  types.ts        MessageKey (キー全部の型)、Part<ns>、PlainKey
  tables.ts       言語 -> 翻訳表
  ja.ts / en.ts / ko.ts / zhHans.ts / zhHant.ts   翻訳表 (名前空間ごとのファイルを束ねるだけ)
  ja/<ns>.ts      日本語 (原文)。キーの正しさの基準
  en/<ns>.ts      英語。Part<ns> 型 = ja に無いキー・足りないキーはコンパイルエラー
  ko/<ns>.ts  zhHans/<ns>.ts  zhHant/<ns>.ts   韓国語・簡体字・繁體字。Partial<Part<ns>> = 足りないキーは許す (訳の途中) が、ja に無いキーと綴りの間違いはコンパイルエラー。zhHant/ は生成物
  dataTexts.ts    tr(table, id, field, ja): データ表の文字の入口 (フェーズ2)。DATA_TEXTS = 言語 -> データ表
  data/en.ts      データ表の英訳 (表ごとのファイル <表の名前>En.ts を束ねる)。ko.ts / zhHans.ts / zhHant.ts も同じ形 (<表の名前>Ko.ts / ZhHans.ts / ZhHant.ts)
  boot.ts         起動時に言語を決める (開発用 ?lang=en ?lang=ko ?lang=zh-Hans ?lang=zh-Hant もここ)
```

コードの識別子 (フォルダ名・ファイル名・変数名) は `ko` `zhHans` `zhHant`、言語のコード (セーブ・`?lang=`・`LANGUAGES`・`navigator.language` の判定) は `ko` `zh-Hans` `zh-Hant`。

### 使い方

```ts
import { t } from '../i18n';

t('home.idleRewards');                              // 放置報酬 / Idle Rewards
t('home.dayReward', { dayOfMonth: 18 });            // 18日目の報酬です / Day 18 reward
```

- キーは `名前空間.(画面.)名前`。`ja/<ns>.ts` のキーは必ず `<ns>.` で始める (チェッカーが見る)。名前空間: `common boot home settings shop gacha quest battle hero mission social alliance tutorial sys transfer village`。
- `{name}` は引数で置き換える。**引数の名前と数は日本語の文から型で決まる**ので、足りない・多いはコンパイルエラー。英語側の `{name}` も日本語と同じ集合でなければならない (チェッカーが見る)。
- 英語の複数形は英語側だけに書く: `'{count, plural, one {# item} other {# items}}'` (`#` は数、`=0 {…}` も使える)。日本語は `{count}個` のまま。
- 大きな数は桁を省略しない (万/億/K/M は使わない)。数字は `String(n)` か `n.toLocaleString('ja-JP')` (= カンマ区切り。英語でも同じ表記) か `formatNumber(n)`。
- 定数の表 (タブの名前など) にはキーを持たせ、描く場所で `t()` する: `const TAB_LABELS: Record<Tab, PlainKey> = { … }` → `t(TAB_LABELS[tab])`。`PlainKey` = 引数の要らないキー。
- 実行時に組み立てるキーだけ `tDynamic(key)`。型の検査が効かないので、できるだけ避ける。

### してはいけないこと: モジュール直下・クラスのフィールドで `t()`

`t()` は呼んだ時点の言語の文字を返すだけで、あとから言語が変わっても変わらない。モジュール直下の定数 (`const X = t(...)`) と、クラスのフィールド初期化子 (`protected readonly screenTitle = t(...)`) は **読み込み時・シーン生成時に1回だけ** 評価されるので、言語を切り替えても古いまま残る。「キーを持たせて描く場所で `t()`」か、フィールドなら getter にする (`protected get screenTitle(): string { return t('…'); }`)。

### 言語が変わったときの画面の更新

画面の文字は `create()` のたびに作り直される (どの画面も、開くたびに全部組み立てる作り)。なので:

1. 設定画面の言語ボタン → セーブの `settings.language` を書き、`setLanguage(code)` → **設定画面を `scene.restart()`** (その場で新しい言語になる)。
2. ほかの画面は、次に開いた時に新しい言語で作られる。ホームに戻ればホームも新しい言語。
3. 起動時は、セーブの言語を `applyLanguageAtBoot()` が適用する (端末にも `abyrus.lang` として覚えておくので、セーブを読む前の画面も同じ言語)。

画像に文字が焼き込んである絵は、言語ごとに用意する (4章)。

### 言語の決まり方

- 新しいセーブ (初回起動): 端末の言語 `navigator.language` が `ja*` → 日本語、`ko*` → 韓国語、中国語 → 簡体字か繁體字 (下)、ほかの言語 → 英語、読めない・空 → 日本語。
  - 中国語は iOS が `zh-Hans-JP` `zh-Hant-TW` `zh-Hans-CN` のような形で返す。**字体 (Hans / Hant) が先、なければ地域、どちらもなければ簡体字**: `zh-Hant*` `zh-TW` `zh-HK` `zh-MO` は繁體字、`zh-Hans*` `zh-CN` `zh-SG` と、地域も字体もない `zh` は簡体字。`zh-Hant-CN` は繁體字、`zh-Hans-TW` は簡体字 (`LANGUAGES` の `match` の、いちばん長く一致するものが勝つ。`tools/tests/i18n.ts` が試す)。`zho` や `zhx` は中国語ではない (英語)。
- 既存のセーブ (`settings.language` が無い): **日本語** のまま (SettingsSystem.restore)。
- 開発中は `?lang=en` `?lang=ko` `?lang=zh-Hans` `?lang=zh-Hant` で、セーブに触れずにその言語で見られる (開発サーバー / 開発環境のみ)。
- 設定画面の言語ボタンは 5 つを 3 + 2 の段で出す (最後の段は中央)。名前は、その言語の文字・フォントで (`日本語` `English` `한국어` `简体中文` `繁體中文`)。画面は何語でも同じ。
- `<html lang>` は、言語を切り替えるたびに言語のコードに合わせる (`ja` `en` `ko` `zh-Hans` `zh-Hant`)。字形の選択のヒントになる。

### 翻訳が無いキー

翻訳が無いキーは、言語の `fallback` の順に落ちる: 英語 → 英語に無ければ日本語。韓国語・簡体字・繁體字は `fallback: ['en']` なので、**訳していない所は英語で出る** (日本語にはならない)。ただし完成扱いの言語は、キーが足りないとコンパイルが通らず、チェッカーも失敗する。作りかけの言語は `Partial<Messages>` 型にして、`LANGUAGES` に `partial: true` を付ける (チェッカーは差を報告するだけ。`npm run i18n:check -- --strict-lang=ko` のように言語を指すと、穴があれば失敗にできる。6 章)。データ表も同じで、行が無ければ、その言語の `fallback` (英語) に落ちる。

## 3. 言語を足す手順

次の言語 (例: タイ語 `th`) を足すとき。韓国語・簡体字・繁體字は、この手順で足してある (ひな形はそれを見る)。

1. `src/game/i18n/languages.ts` の `LANGUAGES` に1行足す: `{ code: 'th', name: 'ไทย', locale: 'th-TH', fallback: ['en'], match: ['th'], partial: true }`。`match` は端末の言語タグの先頭 (小文字)。同じ言語に複数の行が一致するときは、いちばん長い前置が勝つ (中国語の `zh-hant` と `zh`)。`fallback` は翻訳が無いときに先に見る言語。`partial: true` は訳の途中の印 (終わったら外す)。語を空白で区切らない言語・単語が1行より広くなる言語は `ownWrap: true` (下の「折り返し」)。
2. `en/` の形で `th/<ns>.ts` を作る (16 ファイル。最初は中身が空の `Partial<Part<'<ns>'>>`)、`th.ts` (`Partial<Messages>`) で束ねて、`tables.ts` の `TABLES` に足す。コードの識別子 (フォルダ名) は `th`、`zh-Hans` のようにハイフンのあるコードは `zhHans`。
3. データ表: `data/<表の名前>Th.ts` を、`<表の名前>En.ts` の数 (12 ファイル) だけ作り (中身は `{ <表名>: {} }` の `DataTexts`)、`data/th.ts` で束ねて、`dataTexts.ts` の `DATA_TEXTS` に足す。表の名前とファイル: `alliance heroLines heroes items missions schedule shop skills story tutorial village world`。技の種類の札と数字の読み出し (`hero.skill.*`、18 キー) は画面の翻訳表 (手順 2) に入っている。
4. **フォント** (`i18n/fonts.ts`): `FONTS` は `Record<Language, …>` なので、言語を足すとフォントを書かないとコンパイルが通らない。文字を作るときは `fontFamily('sans' | 'serif' | 'black')` を呼ぶ (直書きしない。モジュール直下の定数に入れない: 言語を替えても古いままになる)。画面は、どの画面も開くたびに作り直す作りで、設定画面は言語を替えると自分を作り直すので、フォントも文字と同じ動きで新しい言語になる。
5. 折り返し (`ui/TextLayout.ts`、`ui/CardParts.ts`): 漢字・かな・全角は1字ずつ、スペースで区切る言語 (英語・ハングル) は単語ごと (自動)。ハングルの語が1行より広いときだけ、1字ずつに切る。行頭に来てはいけない記号 (、。」）” ’ · …) と、行末に残してはいけない記号 (「（“ ‘) の禁則は、日本語・中国語で同じ。Phaser 標準の折り返し (`wordWrap`) は空白でしか折らないので、`textWrap(width, advanced?)` で包む (`ownWrap: true` の言語だけ、自前の折り返しに替わる。日本語・英語は今まで通り Phaser のまま)。
6. 数字の区切り: いまは `'ja-JP'` (カンマ)。ko・zh も同じカンマ区切りで、`toLocaleString` が万・억 のように縮めることはない (`tools/tests/i18n.ts` が見る)。ドイツ語・フランス語など区切りが違う言語を足すときは `toLocaleString('ja-JP')` を `formatNumber()` に置き換える。日付 (`2026/11/20`・`11/7 11:59`) も同じ形のまま足りる (ko・zh-Hans・zh-Hant ともに通じる形)。
7. 絵に焼き込んだ文字 (4章) の差し替え。
8. `npm run i18n:check` (穴の数・食い違い)、`node tools/tests/run.mjs i18n` (言語を替えて同じ検査)。検査が言語ごとに見る規則は `tools/i18n/lang-rules.mjs` (6 章)。

### 繁體字は、簡体字から機械で作る

翻訳の量を減らすため、人が訳すのは簡体字 (`zhHans/` と `data/*ZhHans.ts`) だけ。繁體字 (`zhHant/` と `data/*ZhHant.ts`) は、`node tools/i18n/zh-hant.mjs` (または `npm run i18n:hant`) が、簡体字の表を **OpenCC の s2twp** (簡体字 → 台湾の標準字体と言い回し: 软件 → 軟體、信息 → 資訊、鼠标 → 滑鼠) で変換して書き出す。

- 使う道具は `opencc-js` (npm、MIT。辞書は Apache-2.0。開発のときだけ使う devDependency)。`npm install` で入る。
- **構造は変えない**: 非 ASCII の連なりだけを変換する。`{name}`・数字・改行・`%`・`x2` などの ASCII は、そのまま通るので壊れない。変換のたびに、ASCII が同じことを確かめる。引用符は “ ” ‘ ’ → 「 」 『 』 にする (台湾の書き方)。
- 書き出したファイルの先頭には「生成: 直接編集しない」と書いてある。**直接直さない** (次の変換で消える)。台湾の言い回しの直しは `tools/i18n/zh-hant-overrides.json` に書く:
  - `words`: 簡体字の語 → 繁體字の語 (その語が出たら、どの文でも、これを使う。OpenCC より優先。長い語が先)。例 `"账号": "帳號"`
  - `ui`: 画面の文字のキー → 文 (文ごと置き換える。`{name}` と数字は簡体字と同じに)
  - `data`: `表.id.項目` → 文 (データ表の1行)
- 簡体字がまだ空でも動く (空なら空を出す)。簡体字を直したら、`node tools/i18n/zh-hant.mjs` で作り直す。**作り直し忘れは `npm run i18n:check` が見つける** (繁體字の生成物が、簡体字から作った出力と違うと失敗)。`opencc-js` が入っていないときは、この検査は飛ばす。
- 試験 `tools/tests/i18n_zhhant.ts`: 変換が構造を壊さないこと (代わりの変換器で)、繁體字の表のキー・行が簡体字と同じこと、数字・改行・`{name}` が同じこと、簡体字にしかない文字が残っていないこと。
- 台湾の言い回しで OpenCC が直さないもの (校正者が見つけたら `words` に足す): 例 眩晕 → 暈眩 (OpenCC は 眩暈)。

## 4. 絵に文字が焼き込んである所

コードで翻訳できない。見つけたものと扱い:

## 5. 用語集 (英語・韓国語・中国語)

英語は決定済み。**韓国語・簡体字・繁體字は「最初の案」**: 訳す人が、ゲームの文脈で確かめて、直してよい (直したら、この表も直す)。繁體字の列は、簡体字の列を OpenCC (s2twp) で変換したもの (`tools/i18n/zh-hant-overrides.json` の `words` を当てたあと)。台湾の言い回しで直す所は、そこに足す。

### 決めた理由 (ガチャ・クエスト・同盟など)

- **召喚 (ガチャ)**: 英語版は `Summon` で「ガチャ」という語を使わない。韓国語は `소환`、中国語は `召唤` (繁體 `召喚`) にして、英語版の方針に合わせる。理由: (1) 韓国のコレクション RPG は `소환` が標準で、`뽑기` は子どもの遊びの含みがあり、`가챠` はファンの言い方。(2) 中国語は口語の `抽卡` が通じるが、運営の画面の言葉としては `召唤` (『Fate/Grand Order』などがこう呼ぶ) が収まりがよい。ボタンが狭いときは `뽑기` / `抽卡` に替えてよい (替えたら、画面全体で統一する)。
- **クエスト と ミッション**: 英語版は Quest / Missions。中国語は `任务` が両方に当たりやすいので、ミッション = `任务`、クエスト (ステージを進める本編) = `冒险` に分ける。韓国語は `퀘스트` / `미션` で、外来語のまま分かれる。
- **魔晶石** (課金通貨): 日本語の造語なので、韓国語は漢字音 `마정석` (ファンタジーで定着している)、中国語は漢字のまま。**数は全桁**: `1,500 마정석` / `1,500 魔晶石` (万・억・亿・萬 で縮めない)。
- **天井**: 韓国は `천장`、中国は `保底` (どちらも、そのゲームを遊ぶ人が使う言い方)。
- **同盟**: 英語版 `Alliance` に合わせる。`길드` / `公会` の方が多いが、「ギルド」は猟師ギルド (ストーリーの組織) が使っていて、混ざるので。
- **放置報酬**: 韓国は `방치형` の `방치`、中国は `挂机` が、放置ゲームの言い方 (台湾は `放置` も使うが、`掛機` で通じる)。
- **ログインボーナス**: 韓国は `출석 보상` が自然 (`로그인 보너스` は硬い)。
- **キャラ**: 英語版は `Hero`。韓国語 `영웅`、中国語 `英雄` で、英語版に合わせる (`캐릭터` / `角色` も通じるが、混ぜない)。

### キャラ名の決めごと (英語)

- 形は `Name, the Title` (ボスの `Garumudo, the Crimson-Horned Stag`、`Aion, the Infinite Emperor` と同じ)。日本語は「肩書き + 名前」(算盤王ガウス) なので、カタカナの名前 = ローマ字、漢字の肩書き = 意味を訳す (`Gauss, the Abacus King`)。
- 名前の綴りは、キャラの id の綴りのまま (`gauss` → `Gauss`、`touma` → `Touma`)。ギリシャ文字・数学者の名前 (`Phi` `Tau` `Euler` `Godel` ...) もそのまま (Godel の ö は書かない)。キャラではない同盟の疑似メンバーの名前は、ヘボン式で長音を書かない (`Sota` `Toya` `Ko`)。
- 肩書きは 1〜3 語。「Gear」は装備の用語なので、歯車は `Cogwheel`。「Phase」「Summon」など、用語集の語は、肩書きには使わない。
- 狭い所 (名鑑のマス・一覧の行・トースト・ダイアログ・戦闘のパーティバー・ホームの吹き出しの名札) には、名前だけの短い形 `short` (`Gauss`) を出す。広い所 (キャラ詳細・強化・ホームのキャラの見出し) には全部 (`Gauss, the Abacus King`) を出し、幅に収まらなければ縮める。日本語は、どちらも全部 (元のまま)。同じ短い名前のキャラはいない (テストが見る)。
- 画面は `heroNameOf(hero)` / `heroShortOf(hero)` (`data/heroes.ts`) で引く。セーブの `hero.name` は、作られたときの日本語のまま。


### 書き方 (英語)

- 見出し・画面名・ボタンは Title Case (`Idle Rewards`, `Claim All`)。文は普通の文 (`Not enough Gems.`)。
- スキルの文 (`skillsEn.ts`) は同じ効果なら同じ言い回し: 敵単体 one enemy / 敵全体 all enemies / 味方単体 one ally / 味方全体 all allies、強化は raises、弱体は lowers (`lowering its ATK`)、行動封じは stuns、無敵は `making the caster invincible for a short time`、復活は `a fallen ally`、吸収は `drains its HP`。名前は 16 文字までが目安 (キャラ詳細の札は 148 px・太字 19 px。超えると札の中で縮む。戦闘で技を出すと大きく出る)、説明は 80 文字まで (技の一覧で 1 行 = 584 px に収まる。収まらなければ 2 行に折り返す)。日本語の漢数字 (二刀・百矢・千里) は英語でも数 (two / hundred / thousand) を残す (テストが見る)。
- ボタンは短く (1〜2語、できれば 10 文字以内)。収まらないときは文字を小さくせず、言い換えて短くする。
- 日本語の「〜しました」は過去形 (`Idle Rewards claimed`)。「〜です」の文末は丁寧にしすぎない。
- 数・単位: `3 items` (複数形は ICU 形式)、`Lv.12`、`2h 05m`、`×3`。
- セリフ (声) は日本語のまま (チュートリアルの案内文は英訳するが、声は日本語)。
- 画面に収まる長さに言い換える (文字は小さくしない)。目安: ミッションの行の題は 30 字まで、地方のタブは 9 字まで (`region.<id>.tab`)、曜日ダンジョンの一覧の 1 行 (`theme`) は 30 字まで、ボタンの下の小さな札は 10 字まで。長い説明は、折り返す場所に置く。英語にしたら必ず日英のスクリーンショットを並べて、はみ出しを見る。

### キャラ名の決めごと (韓国語・中国語)

英語の決めごと (上) に対応する、韓国語・中国語の最初の案。**形は日本語と同じ「肩書き + 名前」** (英語の `Name, the Title` の倒置はしない): 韓国語 `주판왕 가우스`、簡体字 `算盘王高斯`。名前だけの短い形 `short` は、名前 (`가우스` / `高斯`)。

- **韓国語**: カタカナの名前は、ハングルに音写する (ガウス → 가우스)。**数学者・ギリシャ文字の名前は、韓国の定訳**を使う (Gauss 가우스、Euler 오일러、Gödel 괴델、Phi 파이、Tau 타우 …。定訳が分からないものは、音写して、校正者に確認する)。漢字の肩書きは、意味を訳す (算盤王 → 주판왕)。
- **中国語 (簡体字)**: 漢字の肩書きは、意味を訳す (算盤王 → 算盘王)。カタカナの名前は、音写 (漢字に当てる)。**数学者・ギリシャ文字の名前は、中国の定訳**を使う (Gauss 高斯、Euler 欧拉、Gödel 哥德尔、π 派 …)。
- **繁體字**: 簡体字から機械で作るので、台湾の定訳が違うもの (Euler 欧拉 → 尤拉、Gödel 哥德尔 → 哥德爾 は OpenCC が直す。直らない名前は `zh-hant-overrides.json` の `words` か `data`)。
- 同じ短い名前のキャラはいない (テスト `tools/tests/i18n_data.ts` が、ko・zh でも見る)。
- 名前は 1 つの表 (`heroesKo.ts` / `heroesZhHans.ts`) だけで決める。台詞・ストーリー・スキルの中で名前を呼ぶときも、同じ綴りにする。

### 書き方 (韓国語・中国語)

- **数は全桁**。`10만` `1억` `10万` `1亿` `10K` で縮めない (検査が失敗にする)。`1,500` のようにカンマで区切る。
- 引用符は、**日本語と同じ `「」` `『』` を、韓国語・簡体字・繁體字のどれでも使う**ことを勧める。理由: Latin のフォント (Arial) が、`“ ”` `‘ ’` の幅の狭い字を先に出してしまい、中国語の文字の中で小さく見える。`「」` は中国語・韓国語のフォントの全角で出る。`“ ”` を使ったときは、繁體字の変換が `「」` に直す。
- 韓国語の文末: 画面の説明・ダイアログ・システムメッセージは `~합니다` / `~하세요` (합니다체)。ボタンや見出しは名詞形で終える (`받기` `확인`)。ルリは親しい `~요` (해요체)、教授は冷静な합니다체、猟師ギルド長はぶっきらぼうに。プレイヤーは `사령관님` (軍団長)。
- 中国語の文: 画面の説明は、主語を省いて短く。ストーリーのルリは `你`、教授は `您` (冷静で正確)。
- 名前・ボタン・タブの長さの目安は、全角 1 字が英語の約 2 文字分: スキル名は 8 字、スキルの説明は 40 字、セリフは 33 字まで、ミッションの題は 15 字まで、地方のタブは 5 字まで、ボタンは 5 字まで (校正者用の書き出しの「長さの目安」の列も、同じ)。収まらないときは、文字を小さくせず、言い換えて短くする。
- 語を空白で区切るかどうか: 韓国語は空白で区切る (折り返しは単語ごと)、中国語は空白を入れない (数字・英字の前後に空白を入れる必要はない)。
- `{name}` などの埋め込みは、日本語と同じ名前・同じ数のまま。語順に合わせて位置は動かしてよい。複数形 (`{count, plural, …}`) は使わない (韓国語・中国語には複数形が無い)。

### 校正者向けの書き出し

`node tools/i18n/export.mjs` が、全言語の全文を 1 つの CSV (UTF-8、BOM つき・Excel で開ける、`tools/i18n/out/translations.csv`。git には入れない) に書く。列: `表` `キー` `ja` `en` `ko` `zh-Hans` `zh-Hant` `長さの目安`。`表` は UI の文字なら `ui`、データ表ならその表の名前 (`skill` `hero` `story` …)。`キー` は、UI なら `home.idle.title`、データ表なら `<id>.<項目>` (項目は最後の `.` のあと、id には `.` があってよい: `opening_story.1.text`)。穴 (まだ訳していない所) は空欄。`長さの目安` は、画面の余白が決まっている所だけ (スキル名・スキルの説明・台詞・キャラ名・ミッションの題・地方のタブ・曜日ダンジョンの一覧。英語の字数と、ko・zh の字数)。

**校正の結果を取り込む仕事は、まだ作っていない**。作るとき: CSV の `ko` `zh-Hans` の列を、`表` と `キー` で行に戻して、ko・zh-Hans の表のファイルに書き戻す (繁體字は書き戻さない: 簡体字から作る)。直す人が列を勝手に動かさないこと、改行の入ったセルを壊さないこと、`{name}` と数字が変わっていないこと (`tools/i18n/lang-rules.mjs` の規則) を、取り込むときに見る。

`// i18n-ignore` を付けた行 (またはその次の行) の日本語リテラルは、そのまま残す意味 (パーサーのキーワードなど) としてチェッカーが数えない。

## 7. データ表の文字

キャラ名・スキル・敵・ステージ・ストーリー・アイテムの説明などは `data/` にある。型を変えずに:

```ts
name: tr('hero', hero.id, 'name', hero.name)   // 描く場所で。訳が無ければデータの日本語がそのまま出る
```

訳は `src/game/i18n/data/en.ts` に `{ hero: { <id>: { name: '…' } } }` の形で足す。表ごとに別ファイルにして増やしてよい (`villageEn.ts` `missionsEn.ts` `shopEn.ts` `worldEn.ts` `tutorialEn.ts`、`en.ts` が束ねる)。ID の無い表 (配列) は添字か、日本語名をキーにする。

**行をまとめて包む: `localized()`** (フェーズ2)。表の行 (`name` `description` などの文字の項目) を、読むたびに `tr()` を通す getter にした行に作り替える。呼ぶ側は何も変えなくてよい:

```ts
const ROWS: ShopProduct[] = [ … ];   // 日本語の原文のまま
export const PACKS = ROWS.map((p) => localized('shop', p.id, p, ['name', 'description', 'badge']));
```

- ない項目 (`description?`) は飛ばす。英訳が無い行は日本語のまま出る。
- **getter を持つ行を `{ ...row }` で複製すると、その時の言語の文字に固まる。** 複製するなら表示する場所で読む。オブジェクトに `Object.assign(PREMIUM, …)` のように書き戻す所 (`systems/RemoteShopConfig.ts`) には getter だけのプロパティを置かない (`PREMIUM.name` は文字のまま、画面は `premiumName()` を読む)。
- 運営がサーバーから配る行 (`RemoteShopConfig` の商品、`RemoteInbox` のギフト・メール、お知らせ) は ただのオブジェクトで、文章は書かれたまま。
- ギフトとメールは、セーブに届くときにその時の言語の文字が写される。あとから言語を変えても、届いたものは変わらない (保存済みのセーブの文字は触らない決まり)。
- 理由の文など、画面が日本語の文を探して分岐していた所は、コードを持たせた (`VillageSystem.reasonOf()`)。文を `includes('…')` で探すと、言語を足したときに壊れる。
- 英訳の抜けは `tools/tests/i18n_data.ts` が見つける (英語にして日本語が残っていれば失敗)。表を英訳したら、このテストの `collect()` に足す。同じテストが、日本語と英語で数字 (2 以上) が食い違う行、スキルの漢数字 (二刀・百矢) が英語で消えた行、表にあってデータに無い ID、長すぎる名前・説明も見つける。
- **スキル (`data/skills.ts`)**: 行に ID が無いので、キットの並びで `<heroId>_<slot>` (slot は 0 から) と決めて `localized('skill', …)` で包んである (`HERO_SKILLS`)。スキルの `id` (`kind-日本語名`) は日本語から作ったまま変わらない。**キットの並びを替えるときは `skillsEn.ts` のキーも替える** (テストは「表の ID = キットの ID」までは見るが、入れ替えは見つけられない)。技の種類の札 (`skillKindLabel(kind)`) と数字の読み出し (`formatSkillEffectSummary`) は `t()` (`hero.skill.*`)。技を出した瞬間の名前 (`skillName`) は、そのとき `def.name` を読む。

### 言語を足すとき (簡体字・繁體字・한국어 …)、各表で

韓国語・簡体字・繁體字は、表のファイルを **空の形で作ってある** (`data/<表の名前>{Ko,ZhHans,ZhHant}.ts`、12 ファイル、`skills` なら `skillsKo.ts` `skillsZhHans.ts` `skillsZhHant.ts`)。中身は `{ <表名>: {} }`。訳す人は、英語のファイルを開いて、それと同じ形で埋める。**繁體字のファイルは触らない** (簡体字から生成する、3 章)。

1. 英語の表のファイル (`heroesEn.ts` ...) を見ながら、言葉だけを替える。ID・項目名・並び・`{name}` は変えない。表の名前と中身の対応は上の 12 ファイル: `alliance` (同盟の表と仮のフレンド)、`heroLines` (台詞)、`heroes` (キャラ名)、`items` (素材)、`missions` (ミッション・ギフト・メール・お知らせ・補給)、`schedule` (イベント・召喚・キャンペーン)、`shop`、`skills`、`story`、`tutorial` (`tutorial: { <step id>: { lines } }`)、`village`、`world` (地方・敵・曜日ダンジョン・遠征・装備)。束ねるファイル (`data/ko.ts` など) と `dataTexts.ts` への登録は済んでいる。
2. 表ごとの注意: キャラ名は `name` (全部) と `short` (名前だけ。無ければ全部が出る)。台詞は id ごとに 3 行 (声の番号の順)。ストーリーは `<script id>.<n>` の `text` と、話し手の名札 `storySpeaker` (日本語の名前がキー)。ピックアップの召喚バナーの `description` は、キャラの短い名前と合わせて書き直す (`scheduledGacha`)。イベント通貨の `glyph` と `emblem` は 1 文字。同盟は `allianceSim` を日本語の並びと同じ順で (疑似同盟の名前のつなぎ方は `alliance.sim.allianceName`)。カレンダーが作るお知らせの文は、画面の文字の表 (`social.notice.*`)。
3. 検査は、足した言語にも自動でかかる (`tools/tests/i18n_data.ts` が `ko` `zh-Hans` `zh-Hant` を回す)。英語だけの検査 (名前の形・スキル名の長さ・台詞の長さ・漢数字) は、その言語の決めごと (5 章) で別に足す。訳していない行は、英語で出て検査を通る。**数 (進み具合) は `npm run i18n:check` の穴の数**。

3. **繁體字は訳さない**: `zhHant/` と `data/*ZhHant.ts` は触らない。簡体字を直したら `node tools/i18n/zh-hant.mjs` を回す。台湾の言い回しの直しは `tools/i18n/zh-hant-overrides.json` (3 章)。
4. **用語・名前・引用符・文体・長さ**は 5 章 (用語集・キャラ名の決めごと・書き方 (韓国語・中国語))。迷う語は、まず用語集の案に合わせる。違う語に決めたら、用語集を直す。
5. **進み具合**: `npm run i18n:check` (言語ごとの穴の数)。訳が終わった言語は、`languages.ts` の `partial: true` を外して、型を `Partial<…>` から完全な型 (`Part<'ns'>`・`Messages`) に戻す。型が、足りないキーをコンパイルエラーにする。`--strict-lang=ko` を CI に足すと、穴が戻ってきたら気づける。
6. **確かめ方**: `npx tsc --noEmit`、`npm run i18n:check`、`node tools/tests/run.mjs i18n`。画面は `npm run dev` の `?lang=ko` `?lang=zh-Hans` `?lang=zh-Hant` で見る (セーブに触れない)。はみ出しは必ず画面で見る (文字は小さくしない。短く言い換える)。
7. **大きい数字は、どの言語でも全桁**: `만` `억` `万` `亿` `萬` `K` `M` `B` で縮めない (検査が失敗にする)。
