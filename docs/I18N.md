# 多言語化 (i18n)

ゲームの文字を、日本語 (原文) のまま英語など他の言語でも出せるようにするための仕組みと決めごと。

- 原文は日本語。最初に足す言語は英語。2つ目以降 (簡体字・繁體字・한국어 …) は「翻訳表を1つ足す」だけで済むように作ってある。
- 今回 (フェーズ1) は仕組みと、画面の文字 (ラベル・ボタン・ダイアログ・トースト・システムメッセージ) まで。キャラ名・スキル・セリフ・ストーリーなどデータ表の文字は次のフェーズ (入口の `tr()` だけ用意してある)。

## 2. 仕組み

```
src/game/i18n/
  index.ts        t / tr / getLanguage / setLanguage ... (画面側はここだけ import する)
  core.ts         言語の状態、t()、{name} と複数形の展開、formatNumber
  languages.ts    言語の一覧 (LANGUAGES)、端末の言語の判定 (detectLanguage)、フォールバック順
  types.ts        MessageKey (キー全部の型)、Part<ns>、PlainKey
  tables.ts       言語 -> 翻訳表
  ja.ts / en.ts   翻訳表 (名前空間ごとのファイルを束ねるだけ)
  ja/<ns>.ts      日本語 (原文)。キーの正しさの基準
  en/<ns>.ts      英語。Part<ns> 型 = ja に無いキー・足りないキーはコンパイルエラー
  dataTexts.ts    tr(table, id, field, ja): データ表の文字の入口 (フェーズ2)
  data/en.ts      データ表の英訳 (今は空)
  boot.ts         起動時に言語を決める (開発用 ?lang=en もここ)
```

### 使い方

```ts
import { t } from '../i18n';

t('home.idleRewards');                              // 放置報酬 / Idle Rewards
t('home.dayReward', { dayOfMonth: 18 });            // 18日目の報酬です / Day 18 reward
```

- キーは `名前空間.(画面.)名前`。`ja/<ns>.ts` のキーは必ず `<ns>.` で始める (チェッカーが見る)。名前空間: `common boot home settings shop gacha quest battle hero mission social alliance tutorial sys`。
- `{name}` は引数で置き換える。**引数の名前と数は日本語の文から型で決まる**ので、足りない・多いはコンパイルエラー。英語側の `{name}` も日本語と同じ集合でなければならない (チェッカーが見る)。
- 英語の複数形は英語側だけに書く: `'{count, plural, one {# item} other {# items}}'` (`#` は数、`=0 {…}` も使える)。日本語は `{count}個` のまま。
- 大きな数は桁を省略しない (万/億/K/M は使わない)。数字は `String(n)` か `n.toLocaleString('ja-JP')` (= カンマ区切り。英語でも同じ表記) か `formatNumber(n)`。
- 定数の表 (タブの名前など) にはキーを持たせ、描く場所で `t()` する: `const TAB_LABELS: Record<Tab, PlainKey> = { … }` → `t(TAB_LABELS[tab])`。`PlainKey` = 引数の要らないキー。
- 実行時に組み立てるキーだけ `tDynamic(key)`。型の検査が効かないので、できるだけ避ける。

### してはいけないこと: モジュール直下・クラスのフィールドで `t()`

`t()` は呼んだ時点の言語の文字を返すだけで、あとから言語が変わっても変わらない。モジュール直下の定数 (`const X = t(...)`) と、クラスのフィールド初期化子 (`protected readonly screenTitle = t(...)`) は **読み込み時・シーン生成時に1回だけ** 評価されるので、言語を切り替えても古いまま残る。「キーを持たせて描く場所で `t()`」か、フィールドなら getter にする (`protected get screenTitle(): string { return t('…'); }`)。

### 言語が変わったときの画面の更新

画面の文字は `create()` のたびに作り直される (どの画面も、開くたびに全部組み立てる作り)。なので:

1. 設定画面の言語ボタン → セーブの `settings.language` を書き、`setLanguage(code)` → **設定画面を `scene.restart()`** (その場で新しい言語になる)。
2. ほかの画面は、次に開いた時に新しい言語で作られる。ホームに戻ればホームも新しい言語。
3. 起動時は、セーブの言語を `applyLanguageAtBoot()` が適用する (端末にも `abyrus.lang` として覚えておくので、セーブを読む前の画面も同じ言語)。

画像に文字が焼き込んである絵は、言語ごとに用意する (4章)。

### 言語の決まり方

- 新しいセーブ (初回起動): 端末の言語 `navigator.language` が `ja*` → 日本語、ほかの言語 → 英語 (将来、対応言語を足せばその言語)、読めない・空 → 日本語。
- 既存のセーブ (`settings.language` が無い): **日本語** のまま (SettingsSystem.restore)。
- 開発中は `?lang=en` で、セーブに触れずにその言語で見られる (開発サーバー / 開発環境のみ)。

### 翻訳が無いキー

`en` に無いキーは日本語に落ちる (フォールバック順: その言語 → 設定の `fallback` → 日本語)。ただし完成扱いの言語は、キーが足りないとコンパイルが通らず、チェッカーも失敗する。作りかけの言語は `Partial<Messages>` 型にして、`LANGUAGES` に `partial: true` を付ける (チェッカーは差を報告するだけ)。

## 3. 言語を足す手順

1. `src/game/i18n/languages.ts` の `LANGUAGES` に1行足す: `{ code: 'ko', name: '한국어', locale: 'ko-KR', fallback: ['en'], match: ['ko'] }` (`match` は端末の言語タグの先頭、`fallback` は翻訳が無いときに先に見る言語)。
2. `en/` をコピーして `ko/` を作り (`ko/<ns>.ts`)、`ko.ts` (en.ts と同じ形) を作って `tables.ts` の `TABLES` に足す。最初は `Partial<Messages>` + `partial: true` で始めてよい。
3. `npm run i18n:check` で足りないキー・`{name}` の食い違いを確認。
4. 設定画面の言語ボタンは `LANGUAGES` から自動で増える (3つずつ折り返す)。
5. フォント: いまの文字は `Arial → Hiragino Kaku Gothic ProN → Noto Sans JP → sans-serif`。簡体字・繁體字・ハングルは、それぞれのフォントを後ろに足す必要がある (`ui/theme.ts`、`Toast.ts`、`CardParts.ts`、`RichText.ts` ほか、`fontFamily` を直書きしている所)。ネイティブアプリなら端末の標準フォントで出るが、確認が要る。
6. 折り返し (`ui/TextLayout.ts`): 漢字・かな・全角は1字ずつ、スペースで区切る言語は単語ごと (自動)。ハングルは単語ごと。
7. 数字の区切り: いまは `'ja-JP'` (カンマ)。ドイツ語・フランス語など区切りが違う言語を足すときは `toLocaleString('ja-JP')` を `formatNumber()` に置き換える。
8. 絵に焼き込んだ文字 (4章) の差し替え。

## 4. 絵に文字が焼き込んである所

### 書き方

- 見出し・画面名・ボタンは Title Case (`Idle Rewards`, `Claim All`)。文は普通の文 (`Not enough Gems.`)。
- ボタンは短く (1〜2語、できれば 10 文字以内)。収まらないときは文字を小さくせず、言い換えて短くする。
- 日本語の「〜しました」は過去形 (`Idle Rewards claimed`)。「〜です」の文末は丁寧にしすぎない。
- 数・単位: `3 items` (複数形は ICU 形式)、`Lv.12`、`2h 05m`、`×3`。
- セリフ (声) は日本語のまま (チュートリアルの案内文は英訳するが、声は日本語)。

## 6. 道具

| コマンド | することは |
| --- | --- |
| `npm run i18n:check` | 翻訳表の整合を確かめる (キーの過不足・`{name}`・名前空間・重複。失敗なら終了コード 1)。あわせて、まだ書き込まれている日本語リテラルをファイルごとに数える (報告のみ)。`--list` で行ごと、`--survey` で表だけ、`--strict` で残りがあれば失敗 |
| `npm test` | `tools/tests/i18n.ts` (フォールバック・補間・複数形・言語判定・セーブの移行・コードの `t('キー')` が全部 ja にあるか) を含む |
| `node tools/i18n/migrate.mjs extract <ns> <out-dir> <files…>` | 画面の日本語リテラルを一覧にする (コードは変えない)。`DEFERRED` = モジュール直下など手で直すもの、`MANUAL` = 文字列の連結など人が決めるもの |
| `node tools/i18n/migrate.mjs apply <ns> <out-dir> <en.tsv>` | 英訳 (`id<TAB>英語[<TAB>キー]`) を受けて、リテラルを `t('キー')` に書き換え、`ja/<ns>.ts` と `en/<ns>.ts` に足す。キーは英語から作る (`quest.stageSelect.startBattle`)。`common.*` と日本語が同じなら再利用 |

`// i18n-ignore` を付けた行 (またはその次の行) の日本語リテラルは、そのまま残す意味 (パーサーのキーワードなど) としてチェッカーが数えない。

## 7. データ表の文字 (フェーズ2への入口)

キャラ名・スキル・敵・ステージ・ストーリー・アイテムの説明などは `data/` にある。型を変えずに:

```ts
name: tr('hero', hero.id, 'name', hero.name)   // 描く場所で。訳が無ければデータの日本語がそのまま出る
```

訳は `src/game/i18n/data/en.ts` に `{ hero: { <id>: { name: '…' } } }` の形で足す。表ごとに別ファイルにして増やしてよい。ID の無い表 (配列) は添字か、日本語名をキーにする。
